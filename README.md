# 🎯 GoalTracker Pro

Автономная система управления целями: иерархия целей и подцелей, календарь с заметками, достижения, геймификация (XP, уровни, значки). **Работает полностью офлайн**, устанавливается на телефон как нативное приложение (PWA). Синхронизация с облаком — опциональна.

## 🖥️ Запуск на ноутбуке

```bash
cd ~/goal-tracker
./start.sh          # или: npm start
```

Приложение появится в меню GNOME (поиск «GoalTracker»). Пинните в док: правый клик по иконке → «Добавить в избранное».

## 📱 Режим «Автономный» (по умолчанию, без сервера)

**Никакой сервер не нужен.** Все данные хранятся в браузере телефона/ноутбука (`localStorage`):
- Цели, подцели, прогресс, дедлайны
- Достижения (автосоздаются при завершении целей, защищаются 🔒)
- Календарь с множественными записями в день
- Геймификация: XP, уровни, серии, значки
- Экспорт/импорт JSON, CSV, PDF

### Установка на телефон (PWA)

1. Откройте приложение в Chrome на телефоне (через локальный IP или опубликованную ссылку)
2. Меню ⋮ → **«Установить приложение»** / «Добавить на главный экран»
3. Иконка появится на рабочем столе, откроется **без адресной строки** — как нативное приложение
4. Работает полностью офлайн, данные сохраняются локально

> В настройках (⚙️) есть кнопка **«📱 Установить на главный экран»** — она появится автоматически, когда браузер поддерживает установку.

## ☁️ Опционально: Облачная синхронизация

Если нужна синхронизация между устройствами — опубликуйте в Cloudflare (бесплатно, постоянный адрес).

### Настройка (один раз)

1. Регистрация: <https://dash.cloudflare.com/sign-up>
2. Авторизация CLI:
   ```bash
   cd ~/goal-tracker
   npx wrangler login
   ```
3. Публикация:
   ```bash
   ./deploy.sh               # или: npm run deploy
   ```

Текущая постоянная ссылка:
```
https://goaltracker-pro.sayonara778.workers.dev
```

### Включение синхронизации в приложении

1. Откройте Настройки (⚙️) → раздел «Синхронизация»
2. Включите «Автосинхронизацию»
3. В поле «URL сервера синхронизации» вставьте адрес (например, `https://goaltracker-pro.sayonara778.workers.dev/api/data`)
4. Нажмите «🔄 Синхронизировать сейчас» — данные уйдут в облако

Теперь на другом устройстве откройте ту же ссылку, включите синхронизацию с тем же URL — данные подтянутся автоматически (merge по ID, конфликты решаются по `updatedAt`).

### Обновление версии

После правок кода: `./deploy.sh` — та же ссылка получает новую версию. На телефоне закройте и откройте приложение (Service Worker подхватит обновление).

## 🕳️ Запасные режимы (локальная сеть / туннель)

- `./serve.sh` — локальный сервер, доступ по Wi-Fi: `http://192.168.x.x:8000`
- `./tunnel.sh` — временная публичная ссылка (пока открыт терминал)
- В Настройки → Синхронизация можно указать любой адрес сервера

## 🔄 Как работает синхронизация

- **Автосинхронизация** (опционально): любое изменение уходит на сервер через 2 секунды
- **Ручной запуск**: кнопка 🔄 в сайдбаре или «Сейчас» в Настройки → Синхронизация
- При одновременных правках с двух устройств данные объединяются (union by ID)
- Конфликты решаются по `updatedAt` — если сервер ушёл вперёд, клиент получает 409, объединяет и повторяет
- Настройку автосинхронизации можно выключить в Настройки → Синхронизации

## 🧍 3D-аватар (голограмма-атлет)

На дашборде — виджет с 3D-фигурой в стиле голограммы (светящиеся края, сканирующая полоса, платформа, частицы).

**Своя модель.** Положите файл `assets/avatar.glb` — виджет подхватит его автоматически (масштабируется по высоте 1.8, центрируется, получает тот же голограммный материал). Без файла показывается демо-фигура атлета.

Как получить модель «под себя»:
- **Быстро:** AI photo→3D (Tripo3D, Meshy, Hunyuan3D-2) — 1–4 фото → GLB.
- **Параметрически:** MakeHuman — вводите свои мерки, слайдерами доводите до идеала, экспорт glTF.
- **Сканом:** Polycam/3D Scanner App (iPhone LiDAR) или 80–150 фото → Meshroom/COLMAP → чистка в Blender → GLB.

**Разработка виджета:** код в `src/avatar-widget.js` (ES-модули), сборка `npm run build:avatar` → `avatar.js` (один classic-скрипт — работает и в Electron, где `file://` блокирует ES-модули). Превью: открыть `test/preview.html` при запущенном сервере.

## 🗂️ Структура

```
goal-tracker/
├── index.html      # разметка всех экранов
├── app.js          # логика приложения
├── styles.css      # стили (светлая/тёмная тема)
├── src/
│   └── avatar-widget.js  # 3D-аватар (исходник, ES-модули)
├── avatar.js       # собранная копия виджета (грузится в index.html)
├── assets/         # сюда положить свой avatar.glb
├── main.js         # Electron: окно, уведомления, встроенный сервер
├── server.js       # HTTP-сервер + API синхронизации (/api/data)
├── preload.js      # мост Electron ↔ страница
├── sw.js           # Service Worker (PWA, работает офлайн)
├── manifest.json   # манифест PWA для телефона
├── test/           # smoke-тест и превью виджета
├── serve.sh        # сервер для доступа с телефона
├── start.sh        # быстрый запуск десктопа
└── deploy.sh       # публикация в Cloudflare Workers
```

Данные хранятся в `localStorage` браузера. При включённой синхронизации — также в облачном KV-хранилище Cloudflare.
