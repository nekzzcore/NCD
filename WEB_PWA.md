# NCD в браузере и на телефоне

## Запуск в домашней Wi-Fi сети

Из папки проекта:

```bash
npm run dev -- --host
```

Команда собирает веб-файлы, запускает отдельный статический сервер на `0.0.0.0:8100`
и печатает адреса компьютера. Android SDK, Java и Electron не требуются.
На компьютере откройте `http://localhost:8100`, на телефоне в той же сети —
напечатанный LAN-адрес вида `http://192.168.1.10:8100`.

Другой порт или конкретный интерфейс:

```bash
npm run dev -- --host 192.168.1.10 --port 8200
```

Замените IP адресом своего компьютера. Также доступны `NCD_WEB_HOST`, `NCD_WEB_PORT`
и равнозначная команда `npm run web`. После изменения исходников выполните
`npm run build:web` и обновите страницу. Остановка сервера — **Ctrl+C**.
Компьютер должен оставаться включённым, телефон и компьютер должны видеть друг
друга в сети. Гостевые Wi-Fi сети могут запрещать связь между устройствами.

Сервер отдаёт только собранные файлы `www/`, без файлов профиля, исходников,
ключей и старого `/api/data`. Данные браузера сохраняются через ProfileStorage;
для переноса данных между устройствами войдите в один аккаунт NCD.
Данные принадлежат адресу сайта: HTTP/HTTPS, IP, localhost и разные порты имеют
разные браузерные хранилища. При смене адреса сначала синхронизируйте данные.

## Установка PWA и офлайн-режим

Манифест `manifest.json` содержит название NCD, `display: standalone`, обычные
и maskable-иконки 192/512px. Service worker — существующий `sw.js`.
Он кэширует интерфейс и отдаёт сохранённую страницу при отсутствии сети;
запросы API, авторизованные запросы и метаданные обновлений не кэшируются.
Сначала откройте приложение онлайн и дождитесь загрузки интерфейса и данных.
Для первой авторизации и облачной синхронизации нужен интернет.

На компьютере `localhost` поддерживает service worker. На телефоне обычный
`http://192.168.x.x:8100` позволяет использовать приложение **в браузере**, но
не обеспечивает установку PWA и офлайн-кэш: браузеру нужен безопасный HTTPS-контекст.
`localhost` на телефоне относится к самому телефону, а не к компьютеру.

Для установки с телефона используйте опубликованный HTTPS-сайт NCD либо
локальный HTTPS с сертификатом, доверенным телефоном и выписанным на используемый
адрес. Поддержка уже подготовленного сертификата:

```bash
NCD_HTTPS_CERT=/path/to/cert.pem NCD_HTTPS_KEY=/path/to/key.pem npm run web
```

Сервер не создаёт сертификаты, не меняет доверенные корневые сертификаты,
настройки браузера или firewall. Сертификат и приватный ключ должны находиться
вне `www/` и `public/`. Предупреждение браузера о недоверенном сертификате
не следует считать рабочим безопасным контекстом для PWA.

В Chrome/Android: меню → **Установить приложение** (или кнопка установки в
настройках NCD, когда браузер её предоставляет). В Safari/iOS: **Поделиться →
На экран «Домой» → Добавить**. Установленная PWA открывается без адресной строки.

## Мобильный интерфейс

При ширине до 768px левое меню скрывается, внизу остаются пять основных разделов.
Выбранная цель открывается в шторке поверх списка. Её можно закрыть крестиком,
нажатием на затемнённую область или Escape с аппаратной клавиатуры.
Содержимое шторки прокручивается отдельно; учтены безопасные зоны экрана.
На компьютере детали остаются в правой панели.

Для Live Reload в отдельном нативном Android-приложении по-прежнему используется
`npm run mobile:dev`; его требования описаны в [MOBILE_DEV.md](MOBILE_DEV.md).


## Готовая сборка для Netlify / Vercel

```bash
cd /home/sayonara/goal-tracker
npm run build:web
```

Готовый статический сайт находится в **`dist/web/`** (около 14 МБ).
В этой папке есть index.html, CSS/JS, manifest, service worker и встроенные ресурсы.
Обычная `npm run build` запускает Electron, поэтому для веба используйте именно
`build:web`. Vite в проекте нет. При сборке также обновляются прежние `public/`
и `www/` для совместимости с текущими командами. Каталог `dist/web` пересоздаётся;
не храните в нём исходники или пользовательские данные.

Не публикуйте весь `dist`: там находятся нативные сборки. Не публикуйте корень
проекта: он содержит локальные данные и служебные файлы. Для PWA достаточно `dist/web`;
Node-сервер на хостинге не нужен. Публикуйте сайт в корне выделенного домена,
например `https://имя-сайта.netlify.app/`, а не в подпапке: service worker
регистрируется по `/sw.js`.

### Быстро через Netlify CLI

Нужен аккаунт Netlify. Бесплатный тариф доступен с лимитами использования:
[актуальные условия Netlify](https://www.netlify.com/pricing/).
Из папки проекта выполните:

```bash
npm run build:web
npx netlify-cli login
npx netlify-cli deploy --dir=dist/web --no-build --prod
```

При первом запуске выберите создание нового сайта или привязку к своему сайту.
CLI выдаст постоянный production URL вида `https://имя-сайта.netlify.app` —
его можно отправить на iPhone. HTTPS предоставляет хостинг.
`--no-build` использует уже проверенную локальную сборку; `--prod` публикует
её на основном адресе. Для следующего обновления повторите build:web и deploy
из той же папки. Не меняйте адрес сайта при каждом обновлении: браузерное
хранилище привязано к origin.

В репозитории добавлен `netlify.toml`: Build command — `npm run build:web`,
Publish directory — `dist/web`, Node 22. Это также подходит для Git-деплоя.
`_headers` из сборки задаёт повторную проверку index.html и service worker,
чтобы CDN не удерживал старую оболочку. Netlify CLI учитывает этот файл.
[Официальные параметры deploy](https://cli.netlify.com/commands/deploy/).

Без CLI можно открыть [Netlify Drop](https://app.netlify.com/drop) и загрузить
**только dist/web**. Для повторных обновлений используйте тот же сайт.

### Альтернатива: Vercel CLI

```bash
npm run build:web
npx vercel login
npx vercel dist/web --prod
```

В диалоге укажите свой аккаунт/проект. Для уже собранной папки выбирайте
Framework Preset **Other**, без команды сборки и без дополнительной подпапки
вывода: index.html уже находится в корне загружаемой папки. Не указывайте
`npm run build` для этой загрузки. Команда напечатает адрес production deployment;
используйте постоянный домен проекта для хранения данных и установки PWA.
`--prebuilt` здесь не нужен: он предназначен для специального формата
`.vercel/output`, а не обычной папки статических файлов.
[Документация Vercel deploy](https://vercel.com/docs/cli/deploy).
Бесплатный [Vercel Hobby](https://vercel.com/docs/plans/hobby) предназначен для
личного некоммерческого использования.

### iPhone 15: первый запуск и проверка

1. Откройте production HTTPS-ссылку в Safari и дождитесь полной загрузки.
2. Safari → Поделиться → **На экран «Домой»** → Добавить. Запустите NCD через иконку.
3. Проверьте портрет и landscape: заголовки не закрыты Dynamic Island,
   нижние действия доступны над home indicator; нет горизонтальной прокрутки.
4. Переключите светлую/тёмную тему, откройте форму и клавиатуру. Поле должно
   оставаться доступным после прокрутки; нижнее меню возвращается после закрытия.
5. Создайте запись, дождитесь сохранения, закройте и снова откройте PWA.
   Затем повторите запуск в авиарежиме после первого успешного открытия онлайн.
6. При смене Safari на установленную PWA проверьте наличие профиля отдельно:
   нельзя полагаться на перенос локального хранилища между разными контекстами.
   Для переноса между устройствами/контекстами используйте синхронизацию или экспорт.

Все три apple-mobile-web-app meta-тега включены; status-bar-style установлен
в black-translucent. Добавлена иконка apple-touch-icon 180×180. Для iOS Safari,
PWA и WKWebView применяются safe-area со всех сторон, размер ввода не меньше
16px и обработка VisualViewport для клавиатуры. Приложение сохраняет выбранную
тему; системное оформление полей (`color-scheme`) обновляется при переключении.
Основы safe-area описаны в [документации WebKit](https://webkit.org/blog/7929/designing-websites-for-iphone-x/).

ProfileStorage выбирает IndexedDB в браузере, при недоступности — localStorage.
Это локальные данные конкретного адреса и браузера. Режим Private Browsing,
очистка данных сайта и удаление PWA могут повлиять на сохранность; локальное
хранилище не заменяет резервную копию. Локальные функции не требуют Android API;
Health Connect и Android-системные напоминания в PWA недоступны.

### Проверки этой подготовки

Выполнены `npm run build:web` и целевые Node/JSDOM-проверки PWA, тем, хранилища,
iOS viewport и целостности файлов сборки. Проверяются offline-навигация service
worker, доступность всех precache-ресурсов, восстановление localStorage после
повторного открытия и ошибки записи. Тесты не заменяют настоящий IndexedDB Safari.
Запуск Chrome в этой среде блокируется ограничением сокетов (`Operation not
permitted`); реальная визуальная проверка Safari, IndexedDB и установка на iPhone
15 здесь не выполнены. Публичная ссылка появится после выполнения deploy в аккаунте
хостинга; автоматическая публикация в рамках этой подготовки не выполнялась.


## Исправление загрузки оформления

`build:web` компилирует styles.css через esbuild для Safari 15+ и записывает
результат в public, www и dist/web. В итоговом index.html используется относительная
ссылка `./styles.css?v=<хеш содержимого>`. Service worker кэширует именно эту
версию CSS; новый хеш меняет имя кэша. Внешний импорт Google Fonts удалён:
используются доступные системные шрифты без обязательного сетевого запроса.
Критические переменные тёмной/светлой темы и скрытие неактивных окон находятся
также в HTML, чтобы окна не появлялись списком при недоступном CSS.

Публикуйте всю обновлённую папку www или dist/web либо заново распакуйте
обновлённый dist/NCD-PWA.zip. Старая распакованная папка NCD-PWA на рабочем
столе автоматически не обновляется. После публикации закройте и снова откройте
PWA/вкладку, чтобы обновлённый service worker начал обслуживать страницу.
Не очищайте данные сайта без резервной копии профиля.

Проверены парсинг CSS, ссылки на ресурсы и открытие/закрытие трёх основных
модальных окон в исходном и собранном HTML (Node/JSDOM). Визуальная проверка
реального iOS Safari здесь недоступна. Причина сбоя на удалённом хостинге
без просмотра его сетевых ответов не подтверждена.
