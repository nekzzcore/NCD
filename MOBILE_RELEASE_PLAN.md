# MOBILE_RELEASE_PLAN.md — план мобильного релиза GoalTracker Pro (v1.3.4)

> Статус: черновик, ожидает одобрения. Ничего не собирается и не публикуется до явного подтверждения.

## 0. Что показал аудит (кратко)

- **Архитектура:** офлайн-first vanilla-JS SPA, упакованный **тремя способами**:
  1) Electron 28 (десктоп, `electron-builder`), 2) статический PWA через Cloudflare (`worker.js` + KV), 3) **Capacitor 8** Android (`capacitor.config.ts`, `android/`, appId `com.sayonara.goaltracker`). Плюс **Capgo OTA-обновления** (`@capgo/capacitor-updater`, worker раздаёт `update-*.zip`).
- **Существующий APK:** `GoalTracker_OTA.apk` — реальный Capacitor-билд (не TWA), с Health Connect (`androidx.health.connect:connect-client`) и OTA-плагином.
- **Хранилище:** локально — Electron IPC → Capacitor Preferences → IndexedDB → localStorage-зеркало (`profile-storage.js`); синк — Supabase (RPC `goaltracker_read/write_state` с optimistic concurrency `expected_revision`, код 40001 → retry + 3-way merge, резервные копии при конфликте) и PIN-синк через Cloudflare Worker (409 `stale` при старом `updatedAt`).
- **Git:** репозиторий **отсутствует** (и `/home/sayonara/.git` пуст) — историю допустить/откатить нельзя.
- **Секреты:** service-role/secret ключей в клиенте **нет**; клиент использует publishable ключ (нормально). 🔴 Найден реальный риск: **SYNC_PIN `9198` лежит в `wrangler.jsonc` открытым** при `Access-Control-Allow-Origin: *` — любой может читать/перезаписывать ваш KV-синк.
- **UX-проблемы на узких экранах:** 3D-контейнер фиксирован по высоте (500px) без мобильной адаптации; `user-scalable=no` в viewport; focus-trap/aria-modal только у 2 из ~12 модалок; одиночные `min-width:150px`-элементы могут распирать вёрстку на 360px.

## 1. Этап 0 — «Функции: что работает, что нет» (проверка, без правок UI)

Инструменты: существующие тесты (`npm test`, postgres-тесты — **только в режиме read-only**), ручные проверки запуска web-версии (dev-сервер локально), осмотр кода. Критерий «готово»: поведение подтверждено исполнением, а не синтаксисом.

| Функция | Статус по аудиту | Что проверяем |
|---|---|---|
| Цели/подцели | код обширный + тесты (`goal-storage`, `subgoal-checklist`, `goal-modal`) | создание/редактирование/чек-листы, XP-награды |
| Календарь | есть заметки/события/агенда + тесты | тап по дню, свайп-навигация, модалка влезает в 360px |
| Финансы | отдельный модуль `finance.js` + localStorage | добавление записи, категории, подушка, бюджеты |
| Профиль | прочный стор (Electron/Capacitor/IndexedDB) | аватар-видео, редактирование, сохранность после перезапуска |
| Друзья/чат | `social.js` через Supabase | заявки, поиск по нику, отправка сообщений (только на тестовых данных) |
| Здоровье/3D | three.js 0.186 + Health Connect в APK | рендер, resize, орбит-жесты пальцем; Health Connect — только если реально поддерживается |
| Синхронизация | solida: revision + 3-way merge | конфликт-сценарий ПК↔телефон, ошибки не маскируются под успех |

## 2. Этап 1 — Выбор пути сборки Android

**Решение: Capacitor.**
- Проект **уже** построен на Capacitor 8 с Android-проектом, OTA-плагином и Preferences — продолжаем этот путь.
- PWA оставляем как вспомогательный канал (уже работает через Cloudflare), но основной установкой на телефон делаем APK.
- Electron на Android не трогаем (невозможно и не нужно).

## 3. Этап 2 — Мобильная адаптация UI (минимальные правки; затем v1 накатывается OTA)

1. `viewport`: убрать `user-scalable=no` (доступность), оставить `viewport-fit=cover`.
2. **3D-сцена**: `min/height` контейнера по `@media (max-width:480px)` (~300px), запретить canvas перехватывать прокрутку вне области, включить touch-управление OrbitControls.
3. **Модалки**: везде `role="dialog"`, `aria-modal`, focus-trap и Esc; запирание фона при открытой клавиатуре (visualViewport listener + `padding-bottom`).
4. Мелкие `min-width`-элементы — заменить на `max-width`/flex, убрать риск горизонтальной прокрутки на 360/390/412px.
5. Тонкая нижняя навигация уже есть — проверить touch-зоны ≥48px и подписи на ≤480px.
6. Тёмная/светлая тема: проверить все экраны в обеих темах.
7. Индикация загрузки/ошибок/offline уже частично есть — добавить единый offline-баннер и понятный empty-state.

## 4. Этап 3 — Безопасность и данные

1. 🔴 Вынести SYNC_PIN из `wrangler.jsonc` (rotate PIN, хранить только в `wrangler secret`, не в файле).
2. Убедиться, что в сборку не попадает service-role/secret (проверка по бандлам `www/`, `android/.../assets/public`).
3. Настройка retention/backup при первом входе пользователя (локальный бэкап уже есть в коде — включить поверх).

## 5. Этап 4 — Сборка и тестирование (после вашего одобрения)

1. `npm run build:web` → обновить `www/`; `npx cap sync android`.
2. Локальный debug-APK (`assembleDebug`), установить на ваш телефон.
3. Тесты адаптивности: **360 / 390 / 412 px** + десктоп, тёмная/светлая темы.
4. Сценарий жизненного цикла: установка → запуск → повторный запуск → вход → синхронизация ПК↔телефон → закрытие/открытие (данные не сбрасываются).
5. Отдельно: OTA-обновление через Capgo (без публикации — только локальный канал) проверяется вручную.
6. Health Connect — только если Android-оболочка телефона подтверждена (иначе фича остаётся скрытой).

## 6. Ограничения и стоп-сигналы

- ❌ Не менять боевую базу Supabase (read-only проверки, миграции — только после вашего ОК).
- ❌ Не публиковать APK/AAB и не деплоить OTA до вашего явного «собирай».
- ❌ Не запускать Electron на Android.
- ⚠️ Нет git — рекомендую создать локальный git-репозиторий с первым коммитом **до** любых правок (безопасная точка отката). Это изменение только добавляет файлы, не трогает код.

## 7. Порядок работ по вашему одобрению

1. «ОК на аудит-план» → git init + первый коммит → вносим мобильные правки UI (этап 3).
2. Регресс `npm test` + ручные проверки.
3. Debug-APK → ваши ручные проверки на телефоне.
4. Только после вашего финального ОК — release-подготовка (не автоматически).
