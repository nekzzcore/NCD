# Android Live Reload

Запуск из обычного терминала ноутбука:

```bash
cd /home/sayonara/goal-tracker
npm run mobile:dev
```

Нужны JDK 21, Android SDK, доступный `adb`, включённая USB-отладка и разрешение
отладки на экране телефона. Подключите телефон по USB для первой установки.
Ноутбук и телефон должны находиться в одной Wi-Fi сети: веб-файлы загружаются по LAN,
USB используется для установки и запуска. Скрипт предложит выбрать Android-устройство.

Проверка перед запуском:

```bash
adb devices -l
```

У телефона должен быть статус `device`, а не `unauthorized` или `offline`.
Для явного выбора используйте:

```bash
npm run mobile:dev -- --target DEVICE_ID
```

Если LAN-интерфейсов несколько, укажите имя Wi-Fi интерфейса из `ip -4 addr`:

```bash
MOBILE_DEV_INTERFACE=wlan0 npm run mobile:dev
```

`wlan0` замените фактическим именем интерфейса. Порт по умолчанию — 8100;
изменить его можно переменной `MOBILE_DEV_PORT`. IP автоматически определяется
из интерфейсов ОС; если подходящего адреса нет или выбор неоднозначен, запуск
останавливается с сообщением.

Скрипт печатает URL. Откройте **этот URL в Chrome на телефоне**. Если открывается
GoalTracker, телефон видит сервер ноутбука. Одна сеть Wi-Fi необходима, но гостевая
сеть или изоляция клиентов роутера могут запрещать связь между устройствами.
Если URL недоступен, проверьте сеть и занятость порта; скрипт не меняет firewall,
hosts или системные настройки. Отключать защиту не требуется.

После установки откройте **GoalTracker Dev**. Изменение исходных HTML/CSS/JS,
`src/`, `assets/` или `vendor/` запускает веб-сборку. После её успешного завершения
WebView автоматически перезагружается. При ошибке сборки старая страница остаётся
открыта, ошибка видна в терминале. Изменение нативного кода или плагинов требует
остановки и повторного запуска `mobile:dev`.

## Изоляция разработки

Установленная версия Capacitor 8 поддерживает
`cap run android --live-reload --host HOST --port PORT`; флаг `--external`
относится к Ionic CLI и в этом Capacitor отсутствует.

`mobile:dev` сначала выполняет `build:web`, затем создаёт отдельный Android-проект
в системной временной папке с приватными правами. Только там CLI записывает
`server.url`, разрешает HTTP для разработки и собирает debug-приложение.
Постоянный `capacitor.config.ts` и Android-конфиг рабочего проекта не меняются.
LAN-адрес не записывается в `www/`, `public/` или файлы репозитория.
Рабочие веб-ассеты обновляются обычной сборкой и не содержат dev-вставок.

Dev-приложение имеет application ID `com.sayonara.goaltracker.dev` и отдельное
хранилище. Войдите в облачный аккаунт в нём отдельно. Обычное установленное
приложение не заменяется. Dev-сервер отдаёт только `www/`, без API синхронизации
старого сервера, исходников репозитория, PIN или файлов базы. Автопроверка OTA
выключена только в HTTP-ответе dev-сервера; файлы приложения не изменяются.

Gradle ограничен двумя workers в копии проекта. Укажите `JAVA_HOME` для JDK 21
и `ANDROID_HOME` для SDK, если они не настроены в вашем терминале.

Остановка — **Ctrl+C**. Сервер останавливается, временный проект удаляется.
Dev-приложение остаётся на телефоне и без сервера не работает; его можно удалить.
После аварийного выключения временная папка может остаться в системном temp,
но она находится вне репозитория и каталогов публикации.

Этот режим предназначен только для разработки в доверенной общей Wi-Fi сети.
Не используйте dev-APK для финальной сборки, Telegram-раздачи или OTA.
Обычный production-процесс остаётся `build:web` → `cap copy android` → Gradle
в рабочем Android-проекте, без Live Reload.

В ограниченном окружении агента запуск сервера, ADB и Gradle может блокироваться
с `Operation not permitted`. В таком случае запускайте команду в обычном локальном
терминале; скрипт не пытается обходить ограничения.
