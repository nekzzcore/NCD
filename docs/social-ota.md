# Друзья и OTA

Перед публикацией клиента примените `supabase/migrations/20261025_social_handles.sql` в SQL Editor проекта Supabase. Миграция добавляет и заполняет profiles.handle, уникальный индекс, триггер заполнения и RPC social_search_handle. Старые повторяющиеся имена получают стабильные user_… ID. Имена для отображения сохраняются. RLS не меняется; RPC доступна только authenticated и возвращает только UUID и handle.

Проверка: войдите двумя аккаунтами, скопируйте ID первого, найдите его со второго с @ и без, отправьте заявку, примите её и откройте чат. Повторите с отклонением заявки и выходом из аккаунта.

`npm run deploy` увеличивает patch-версию, собирает веб-ассеты, создаёт ZIP с SHA-256, публикует Worker и загружает архив в Cloudflare KV. Метаданные версии публикуются последними и указывают на архив конкретной версии. Требуется авторизация Wrangler (`npx wrangler login`). Можно передать версию и описание: `npm run deploy -- 1.3.6 "Исправления друзей"`. Только сайт: `npm run deploy:site`.

Worker: https://goaltracker-pro.nekzzcore.workers.dev; проверка обновлений: /version.json. Ручную загрузку и установку через CapacitorUpdater выполняет app.js. В capacitor.config.ts выключены автоматические проверки Capgo, чтобы не запускать второй механизм обновления.

Проверка на телефоне: откройте установленную более раннюю версию после деплоя, дождитесь загрузки и перезапуска, проверьте версию и сохранность данных; затем повторите запуск без сети. OTA обновляет веб-код. Установленный APK должен уже содержать нативный CapacitorUpdater; изменения нативных плагинов требуют новой APK-сборки.

В текущей среде ответ Worker не проверен: DNS домена недоступен. SQL-миграция подготовлена, но не применена к удалённой базе.

## Живая уникальность handle

На втором шаге регистрации проверка запускается через 300 мс после ввода. Сначала клиент читает только `profiles.handle` по точному нормализованному значению. Если запись не видна или RLS запрещает чтение, `ncd_handle_available` проверяет занятость на сервере без раскрытия профиля. Перед публикацией примените `supabase/migrations/20261025_strict_handle_availability.sql`: функция проверяет и profiles.handle, и ещё не подтверждённые регистрации в auth.users. UNIQUE не меняется. При сетевых ошибках или отсутствии функции кнопка остаётся заблокированной.

Для проверки двух устройств используйте два разных аккаунта: после входа сравните «Ваш ID» с handle соответствующей строки profiles; затем выйдите и поменяйте аккаунты местами. Автоматические тесты проверяют тот же сценарий на двух изолированных клиентах.
