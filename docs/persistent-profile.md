# Постоянный локальный профиль

## Причина повторной регистрации

`applyRemote()` оставлял `this.user` в памяти при ответе сервера без `user`, но
сохранял исходный ответ без профиля в `goalTracker_data`. После перезапуска
`loadData()` получал пустой профиль. Дополнительно `logout()` записывал `user: null`,
а ошибки чтения localStorage скрывались и последующий `initTheme()` мог сохранить
пустое состояние. Это не было очисткой данных самим механизмом обновлений.

## Хранение

- Electron: атомарный `profile.json` в `app.getPath('userData')`, на Linux по
  умолчанию `~/.config/goaltracker-pro/profile.json`. Каталог стабилен для dev и
  установленной версии; явно заданный `--user-data-dir` учитывается.
- Capacitor: официальный плагин Preferences, вне каталога обновляемых ассетов.
  Для старых APK без плагина используется браузерное хранилище; добавление плагина
  требует следующей нативной сборки. Автоматически APK не собирается.
- PWA: IndexedDB `goaltracker-profile`, store `profile`.
- localStorage `goalTracker_data` остаётся совместимым зеркалом и источником
  миграции. Данные не хранятся в Cache Storage сервис-воркера.

Миграция добавляет `schemaVersion: 1` и постоянный `user.id`, сохраняя поля данных.
Electron может восстановить отсутствующий профиль из прежнего `data.json`.
Неизвестная новая схема или повреждённое хранилище останавливают инициализацию
без перезаписи данных. Сброс записывает маркер `profileReset`, чтобы старые копии
не восстановили удалённый профиль автоматически. Серверные копии сброс не удаляет.

Supabase SDK и аккаунт не настроены. Фиктивные email-регистрация и вход удалены;
профиль локальный, синхронизация по явно заданному URL остаётся опциональной.

## Проверки

```sh
npm run build:storage
node --test test/profile-store.test.cjs
node test/profile.persistence.cjs
node_modules/.bin/electron test/video.smoke.cjs
npm run build:web
npx cap sync android
npm run build:linux -- --dir
```

`profile.persistence.cjs` использует отдельные процессы, временные каталоги и
копию веб-бандла. Проверяет создание, реальный перезапуск, новую версию приложения
и service worker, сохранение ID/целей/заметок, частичную синхронизацию, сброс с
подтверждением, миграцию и защиту повреждённых данных. Рабочий профиль не используется.
`cap sync` подготавливает Android-проект, не собирает APK. Физическое Android-устройство
нужно проверить отдельно после следующей нативной сборки.
