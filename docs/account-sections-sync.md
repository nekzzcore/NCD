# Синхронизация разделов аккаунта — 1.3.35

Общая синхронизация остаётся основным путём. При ошибке отдельной таблицы клиент
независимо подтверждает цели, календарь, операции, подушку, бюджет и инвестиции,
Case/Обучение, здоровье и профиль с привычками и достижениями. Отказ одного
раздела не превращается в пустые данные другого. Статус перечисляет успешно
подтверждённые разделы и отдельные ошибки; он не обозначает неотправленное как
сохранённое.

Для каждого раздела выполняются чтение своего владельца, трёхстороннее объединение,
запись при наличии изменений, повторное чтение после записи и обновление только
подтверждённой части baseline. Остальные записи и незавершённые изменения остаются
на устройстве. JSON-документы обновляются с условием версии; конфликт не стирает
несинхронизированную копию. Возвращение в сеть запускает отложенный обмен.

Календарь использует `calendar_events`; для старой схемы событий применяется
`user_profile.data.__goaltrackerSync.calendar`. Case/Обучение используют проверенные
JSON-поля `profiles` либо существующий документ `user_profile.data.workspace`.
Бюджет и инвестиции находятся в `__goaltrackerSync.financeOther`.

При отсутствующих столбцах/таблице финансов (например, `42703`) операции могут
храниться в `user_profile.data.__goaltrackerSync.transactions` с маркером
`transactionsStorage: "profile-v1"`. Маркер сохраняет выбранный путь на других
устройствах, даже если исходная таблица позднее станет доступна. Исходная таблица
не удаляется и не изменяется ради переноса. Сохранившиеся локальные операции
сначала объединяются с новым хранилищем. Запрет доступа `42501` не маскируется
этим переключением. Все запросы используют авторизованную сессию и фильтр владельца.
SQL-миграция и административные ключи для этих JSON-полей не нужны.

Здоровье передаёт только последние значения шагов, пульса, сна и веса с источником
и временем измерения (`user_profile.data.health`). При независимых изменениях
показаний выбирается более свежее измерение каждого типа. Разрешения Health Connect
и состояние подключения не передаются; чтение датчиков возможно только на Android.
Последние значения доступны для отображения на ноутбуке без нативного адаптера.

Для работы нового обмена нужно обновить телефон и перезапустить настольный NCD,
чтобы оба клиента использовали 1.3.35. В APK внутренний `versionCode` соответствует
версии (1003035), поэтому старый скачанный OTA-бандл не подменяет новый встроенный.
Автотесты проверяют два клиента, офлайн-правки, ошибки схемы, конфликты документов
и изоляцию аккаунтов; они не заменяют проверку доступа к реальному Supabase.
